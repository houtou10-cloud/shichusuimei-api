## 1. エンジンの目的・設計原則

八雲式四柱推命鑑定エンジンは、生年月日・出生時刻・出生地等の入力から命式を算出し、四柱推命の各種判定を構造化したうえで、AIによる鑑定文章およびPDF鑑定書生成へ接続することを目的とする。

基本パイプラインは次の通り。

`入力 → 暦・四柱 → 蔵干 → 通変星 → 十二運 → 五行 → 月令・通根 → 身強身弱 → 干支関係 → 格局 → 用神 → 大運・歳運・現在運 → reading context → AI鑑定 → 品質検査 → PDF`

### 1.1 設計原則

1.  決定論的な計算は Python エンジン側で行う。
2.  AI に命式計算や格局決定などの確定計算を丸投げしない。
3.  AI
    は構造化された計算結果を、人間が理解できる鑑定文章へ翻訳する役割を中心とする。
4.  判定結果だけでなく、可能な限り判定根拠を保持する。
5.  単一要素だけで人物・吉凶を断定しない。
6.  境界・例外・複数候補を許容できる構造を目指す。
7.  v1.1 の挙動を回帰テストで固定し、v1.2 の変更は明示的に行う。

## 3. 暦・四柱算出仕様

### 3.1 入力

少なくとも以下を入力として扱う設計が確認されている。

-   生年月日
-   出生時刻
-   出生地
-   性別

### 3.2 四柱

出力する基本四柱。

-   年柱
-   月柱
-   日柱
-   時柱

各柱は天干＋地支から構成する。

### 3.3 現行ルールとして確認されている事項

過去レスポンスでは以下の計算ルールが表示されていた。

-   年: 立春基準の処理
-   月: 節入り基準
-   日: 00:00 境界
-   時: 子刻 23:00〜00:59 を含む時刻区分

ただし、過去の開発段階では `solar_terms.py`
に暫定的な固定節入り処理が存在し、節入り日付近には警告を出す設計が確認されている。

### 3.4 v1.1 の制約

-   真太陽時補正は現行仕様として確定実装されたものとは扱わない。
-   出生地による地方時補正も、v1.1固定仕様としては未確認。
-   節入り境界の天文計算精密化は v1.2 以降の重要候補。

## 8. 月令・季節評価仕様

## 11. 身強身弱仕様

関連モジュール:

-   `day_master_strength.py`
-   `final_strength_judgment.py`

単純多数決ではなく、複数要素を重み付けした総合判定を行う。

過去テストで確認された例:

``` text
label = やや身強寄り
final_score = 53.5
base_supporting_ratio = 55.0

adjustments:
  weighted_root_bonus = 4.5
  seasonal_adjustment = -6.0

evidence:
  total_root_score = 0.45
  seasonal_state = 囚
  seasonal_score = -6.0

method = weighted_provisional_strength_v2
status = provisional_weighted_judgment
```

生成済み鑑定書では別ケースとして `46.55 / 中和` の出力も確認されている。

### 11.1 設計上の重要点

-   日主を基準とする。
-   生助と剋洩耗を区別する。
-   月令を重要要素として扱う。
-   通根を加重評価する。
-   季節補正を行う。
-   月令の二重加算を避ける。
-   最終スコアとラベルを返す。
-   根拠情報を保持する。

### 11.2 v1.2で固定すべき事項

-   ラベル境界値
-   各補正値
-   極端な命式の扱い
-   中和域
-   上限・下限
-   境界値テスト

## 16. 出生時刻不明（三柱）仕様

出生時刻が不明なケースでも、年柱・月柱・日柱を中心に処理する三柱モードが実装されている。

### 原則

-   時柱を推測して確定値として扱わない。
-   時柱依存の判定は制限または不確実性を明示する。
-   四柱モードと三柱モードで同じ確信度を装わない。
-   AI文章にも出生時刻不明を伝播させる。

詳細な除外対象・confidenceルールは最新コードとの照合が必要。

## 17. reading_context 仕様

エンジンの計算結果を AI 鑑定へ渡すための構造化コンテキスト層。

目的:

-   AIに生の命式を再計算させない。
-   確定値と推論値を区別する。
-   鑑定テーマ別に必要情報を整理する。
-   AI文章とエンジン結果の不整合を減らす。

v1.2では schema version を明示し、後方互換性を管理することを推奨する。

## 18. AI鑑定生成仕様

AIの役割は、エンジンの構造化結果を自然言語へ翻訳すること。

-   健康傾向
-   現在の運勢

### 原則

-   将来を保証しない。
-   不確実な情報は不確実として扱う。

は「完成していない」という意味だけではなく、ルールバージョンを明示するメタデータとして重要。

v1.2では全主要判定について、

-   `method`
-   `version`
-   `status`
-   `evidence`
-   `warnings`

を共通形式へ寄せることを推奨する。

## 30. 四柱推命アカデミー連動を見据えた将来仕様

`講義 → 問題 → 自己回答 → エンジン判定 → evidence → 復習講義`

# 付録C: 仕様書の運用ルール

1.  `v1.1` 本文は原則として過去仕様の記録として残す。
